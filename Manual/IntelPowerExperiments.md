# Intel graphics power experiments

These boot arguments target a display-connected Kaby Lake, Coffee Lake or Comet Lake iGPU using the Apple KBL/CFL framebuffer. The default is off. Remove the experimental arguments and reboot to return to your previous settings. Keep a bootable copy of your previous EFI when testing display policy.

| Boot argument | Behaviour |
| --- | --- |
| `igfxpwr=1` | Collect RC6 residency, observed ForceWake requests, and display registers already read by the Apple framebuffer. No new timer. |
| `igfxpwr=3` | Diagnostics plus a request for native FBC (`0x4`). `weg-power-fbc-enabled` and `weg-power-fbc-compressing` show whether it is in use. |
| `igfxpwr=257` | Observe the native FBC policy. Bit 256 no longer forces dynamic FBC. |
| `igfxpwr=5` | Diagnostics plus a request for native dynamic CDCLK. `weg-power-cdclk-transition-observed` shows whether the clock changed. |
| `igfxpwr=9 igfxrpsc=1` | Diagnostics plus an HWP-aware limit on WhateverGreen's adaptive RP0 boost. |
| `igfxrpsc=3` | Measures GT load from the hardware RP busy counters (`weg-rps-busy-permille`). Never changes the frequency. |
| `igfxrpsc=4` | Boosts to RP0 only while the measured hardware load stays high. Combine with `igfxpwr=8` to defer it while the CPU prefers power saving. |
| `igfxpwr=17` | Diagnostics plus PSR off: the enable bit is cleared from the framebuffer's PSR1/PSR2 control writes. |
| `igfxpwr=33` | Diagnostics plus DC states limited to DC5: a DC6 request is written as DC5. |
| `igfxpwr=65` | Diagnostics plus DC5/DC6 off. |
| `igfxpwr=129` | Diagnostics plus native modeset: WhateverGreen's forced complete modeset is turned off so the Apple driver decides. |
| `igfxfcms=0` | Existing independent option with the same modeset effect; `igfxfcms` and `complete-modeset` take precedence over `igfxpwr=128`. |

The decimal mask accepts bits 1 (observe), 2 (FBC), 4 (CDCLK), 8 (EPP, includes observation), 16 (PSR off), 32 (DC5 limit), 64 (DC5/DC6 off), 128 (native modeset) and 256 (observe native dynamic FBC). The forced dynamic FBC path caused a panic in testing. Its underlying cause is unresolved. Bits 2, 4 and 256 also turn on observation, so the FBC and CDCLK registers can confirm the request. Try one policy change per boot. The display options merge flags into the selected platform entry only; an explicit enabled `framebuffer-flags` patch takes precedence. The Apple controller publishes `weg-power-framebuffer-flags` when a matching entry is found. Existing platform capabilities, panel support, and driver policy still apply. CDCLK additionally depends on Apple's `SupportDynamicCDClk=1` and `dc6config=3`. This experiment manipulates neither PLLs nor display watermarks.

## Reading a sample

Run this after using the desktop for a few seconds:

```sh
ioreg -lw0 -p IOService | grep '"weg-power-'
```

* `weg-power-rc6-permille` is the share of the measured interval spent in GT RC6, from 0 through 1000. A value of 900 means 90%. Check `weg-power-window-ms`, `weg-power-status`, and the uptime of the last sample in `weg-power-uptime-s`. GPU notifications drive sampling at most once every five seconds. A fully idle GPU may leave an old sample visible. The first sample establishes a baseline. The residency counter (0x138108) is outside the GT ForceWake ranges, so it is sampled whether or not the render well is awake; a zero or all-ones read starts a new baseline. A wake from sleep also starts a new baseline. An incompatible counter delta, incompatible counter delta, long gap or wall-clock discontinuity invalidates the window.
* `weg-power-fbc-enabled` is bit 31 of the last FBC control read, `weg-power-fbc-compressing` whether the last FBC status read showed compressed segments, and `weg-power-fbc-status2-raw` the raw status. `weg-power-cdclk-transition-observed` is `1` once two CDCLK control reads in the same wake cycle had different frequency fields. Display values are cleared at each wake from sleep.
* With `weg-power-forcewake-hook=1`, the render, media and blitter counters show the observed set/clear calls to Apple's SafeForceWakeMultithreaded entry. The context masks show the last observed request per context, before hardware acknowledgement. Values are approximate concurrent snapshots. Repeated requests for the same bit, driver paths outside the hook, and in-flight transitions prevent deriving a driver's ownership count or a confirmed leak.
* PSR1/PSR2 status, FBC control, CDCLK control, DC policy, and DC3-to-DC5 / DC5-to-DC6 transition counters are **last observed** native reads. An absent property means no usable read has been captured and published. A zero policy value or unchanged counter alone cannot establish time spent in a state. PSR and DC transitions continue to be managed by Apple and the panel/DMC.
* The EPP option samples a worker CPU's HWP request, including package delegation when selected. An available EPP of 128–255 defers the extra adaptive RP0 request for up to ten seconds after each sample. Apple's requested frequency is preserved during that interval. Read failures expire the hint. Mode 2 retains its existing behaviour. This option makes no MSR or package power-limit writes.
* ForceWake holds: `weg-power-fw-<domain>-longest-hold-ms` is how long the oldest context bit has been requested on that domain without a clear, and `weg-power-fw-<domain>-longest-holder` is that context bit. `weg-power-fw-<domain>-ack` is the hardware ACK of the context bits (absent when the read failed). A hold counts only while its bit is set in that ACK and it started after the last wake. `weg-power-fw-leak-suspect` has one bit per domain (1 render, 2 media, 4 blitter) whose longest hold reached 30 s; such a hold keeps the GT out of RC6. Holds are per requested context bit, not Apple's internal reference count, so a short-lived nested request can end a hold early.
* With the EPP option, the boost follows the CPU's preference in both directions: EPP 128–255 defers WhateverGreen's extra RP0 request, EPP 0–63 lets `igfxrpsc=1` boost after one busy interval instead of two, and 64–127 keeps the default. `weg-power-boost-bias` shows the current choice.
* PSR, DC and modeset policies only lower what Apple's driver requests. They cannot turn on PSR the panel or driver did not enable, or allow a deeper DC state than the driver asked for. `weg-power-psr1-writes-cleared`, `weg-power-psr2-writes-cleared` and `weg-power-dc-writes-limited` count the changed writes (published with diagnostics); 0 means the driver did not request that state through WriteRegister32. `weg-power-psr-policy`, `weg-power-dc-policy` and `weg-power-native-modeset` confirm the selected policy.
* Turning PSR or DC states off normally costs power; use it to check whether a flicker, wake or black-screen problem comes from them, or as the baseline of an A/B test. If the Apple driver waits for a PSR or DC state it requested, the wait can time out; remove the option if wake or display changes become slow.
* `igfxrpsc=3`, `4` and `5` read RP_CONTROL (0xA024) and the current up-interval counters (0xA050, 0xA054) at most every 20 ms during Apple's PM notifications. A ForceWake ACK of 0 only means nobody holds ForceWake, not that the GT is asleep, so each sample also reads the RC6 residency counter (0x138108, readable without ForceWake). With an ACK, the reads count when the ACK is unchanged afterwards. Without one, a GT that spent at least 40% of the time since the previous sample in RC6 was busy at most the rest, which is below the boost threshold: that upper bound is used (`rc6-bound`) and no GT register is read. Otherwise the GT registers are read and count only if the residency did not advance during the reads, i.e. the GT stayed awake (`sampled-awake`); a GT in RC6 reads as 0 and is rejected. A read is accepted only with busy-average up-evaluation enabled, a plausible interval and new values. `4` boosts after three consecutive samples at 85% busy or more and keeps the boost while the load stays above 60%; a gap in samples or a wake from sleep resets it. `weg-rps-busy-permille`, `weg-rps-high-load` and `weg-rps-busy-status` are published about once a second. When `weg-rps-busy-status` says `counter unavailable`, it also names the reason. `weg-rps-busy-count-*` count every sample since boot by result (`sampled`, `sampled-awake`, `rc6-bound`, `no-controller`, `gt-asleep`, `rp-mode`, `implausible`, `unchanged`). `weg-rps-gt-ack-raw`, `weg-rps-rp-control-raw`, `weg-rps-up-ei-begin`, `weg-rps-up-busy` and `weg-rps-up-ei-end` are the raw reads of the latest sample, and `weg-rps-rc6-idle-permille` its RC6 share since the previous sample (4294967295, shown by ioreg as 18446744073709551615, = not read or unknown). With `rp-mode`, the RP_CONTROL value shows how Apple's driver configured hardware RPS evaluation.
* `weg-power-events-dropped` counts events that did not fit in the 8-entry log queue. Events queued before a sleep are discarded after wake.
* `-igfxrc6fix` is a separate existing control for RC6 repair. It is unnecessary for observation.

For an A/B test, use the same brightness, panel mode, AC/battery state and workload. Compare multiple equal-duration idle and video intervals; include wake, lid open/close and external-display reconnect after changing display flags. Use independent power measurements for watts or battery life.

## Load, power and thermal policy

Use `igfxrpsc=5` for the three-tier Gen9 policy. Below 60% measured busy, preserve the Apple request. At 60% or more, the extra request can reach the midpoint between the fused RPn and RP0. Three consecutive samples at 85% or more permit RP0. Battery power or a sampled core thermal margin of 15–24 °C limits the extra request to the midpoint. A smaller margin, active thermal throttling, missing power data or an unavailable sensor leaves the driver in control. These thresholds are experimental. The AC state comes from the first `IOPMPowerSource` that reports `ExternalConnected` and is looked up at most every 10 s and after each wake (`weg-rps-power-source`: `AC`, `battery` or `unknown`). Like mode 4, mode 5 needs readable busy counters: while `weg-rps-busy-status` reports `counter unavailable`, the measured tier stays 0 and Apple's request is kept. Policy inputs are sampled in the deferred worker. Notifications drive load sampling at most every 20 ms, backing off to 80 ms below 30% busy or after an invalid counter read.

Mode 5 publishes estimated observed time in frequency bands below 500 MHz, 500–899 MHz and at least 900 MHz under `weg-gt-*`. Display observation (`igfxpwr=1`) reports PSR1 buffer-off and PSR2 deep-sleep milliseconds alongside each stream's covered milliseconds. The profilers count intervals up to 250 ms between observations in the same state, exclude wake boundaries when a wake timestamp is available and omit unobserved time. The two PSR streams have independent coverage.

With `-igfxrc6fix`, the monitor reports a verified restore only after residency advances. A failed verification suspends recovery. A new wake epoch or a minute of stable driver enablement rearms it. With `-igfxbls`, a one-shot timer schedules each fade step on the existing workloop.

## Reset-aware recovery and additional counters

On KBL/CFL/CML, RC6 repair requires every dependent register to match the saved driver configuration. It writes only the RC6 enable bit and verifies the readback and subsequent residency movement. If the configuration is incomplete it waits for Apple to reinitialize it. A native framebuffer GDRST write observed through the shared MMIO hook invalidates the snapshot and load history. The generation counts observed reset requests; direct accelerator / firmware resets can bypass this hook. Checks around a write cannot serialize it against unobserved driver accesses.

Modes 3–5 can derive busy time from one minus the down-window idle fraction when the up-window sample is unavailable and RP_CONTROL selects down-idle-average. The status and per-path counters report which source produced a sample. Invalid or repeated samples leave the native frequency request in effect.

Mode 5 applies the more restrictive of the worker core's and the supported package sensor's thermal limits. Native battery change notifications invalidate the cached power policy until the next worker refresh. The periodic lookup remains available for providers that do not deliver notifications.

Mode 5 publishes a 256-byte little-endian histogram in `weg-gt-50mhz-bins-ms`. Each UInt64 is estimated observed milliseconds; bin 0 covers frequencies below 50 MHz and bin 31 covers 1550 MHz and above. Samples with missing or zero clock readback break coverage. Equal-band observations separated by at most 250 ms contribute time. GPU sleep and missing observations can leave long gaps.

Add `-igfxvblboost` alongside `igfxrpsc=5` to test promotion of an existing intermediate-tier request near the next predicted VBL of the IGPU's framebuffer zero. Only the last tenth of a period and projections younger than six periods qualify. The worker refreshes timing during reporting; coverage is intermittent. Heat, AC/battery policy and EPP keep precedence. `weg-rps-vbl-promotions` counts policy decisions. VBL timing is a display deadline proxy, not a per-command completion deadline.

Gen9 display counters expose DC5/DC6 entries. The `weg-dc5-entries-per-minute` and `weg-dc6-entries-per-minute` properties use native register observations 1–60 seconds apart and exclude counter decreases, observed resets and known wake boundaries. They measure transition frequency. Measuring time spent inside DC5/DC6 requires a separate residency source.

The experimental FBC request checks the integrated GPU's GMS field against the selected framebuffer's memory budget before adding its flag. Unrecognized allocations and insufficient memory suppress the extra request. `weg-fbc-dvmt-mb` and `weg-fbc-platform-budget-ok` report this preflight. Actual compression still depends on the active mode and driver allocations; check `weg-power-fbc-compressing`. Dynamic FBC remains under native policy. The backlight smoother coalesces identical pending nonzero PWM requests and executes screen-off immediately.
